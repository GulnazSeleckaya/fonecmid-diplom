# Инструкция по начальной настройке конфигурации
 
## Введение
Данная инструкция предназначена для специалистов заказчика и описывает шаги по включению и начальной настройке разработанной функциональности в действующей информационной базе.

### Описание действий

### 1. Обновление конфигурации
Установите обновление конфигурации в режиме Конфигуратора.
Запустите информационную базу в режиме предприятия и убедитесь, что ошибок при запуске нет.
Проверьте, что в интерфейсе появились новые подсистемы:
Обслуживание клиентов, 
Расчет управленческой зарплаты И
Отчеты

------

### 2. Заполнение констант
Перед началом работы необходимо заполнить константы, которые используются в механизмах обслуживания клиентов и автозаполнения документов реализации.
Порядок заполнения:

Откройте раздел «Обслуживание клиентов» → «Сервис».
Заполните константу Токен управления телеграм-ботом — получите токен у @BotFather в Telegram.
Заполните константу Идентификатор группы для оповещания — узнайте ID группы, куда бот добавлен администратором.
Создайте или выберите элементы справочника «Номенклатура» для абонентской платы и работ специалиста (вид — услуга).
Укажите ссылки на эти элементы в константах Номенклатура абонентская плата и Номенклатура работы специалиста.
Без заполнения констант номенклатуры автозаполнение документов Реализация и массовое создание актов работать не будут.

------

### 3. Настройка договоров абонентского обслуживания
Для работы с клиентами по модели абонентского обслуживания необходимо настроить договоры.

Откройте справочник «Договоры контрагентов».
Создайте новый договор или откройте существующий.
В поле «Вид договора» выберите значение Абонентское обслуживание (новое значение перечисления Виды Договоров Контрагентов).
После выбора вида договора на форме появятся дополнительные реквизиты:
Дата начала действия договора
Дата окончания действия договора
Сумма ежемесячной абонентской платы
Стоимость часа работы специалиста
Заполните все четыре реквизита и сохраните договор.
При проведении документа «Обслуживание клиента» система проверяет, что выбран договор вида «Абонентское обслуживание» и что дата документа находится в пределах периода действия договора.

------

### 4. Настройка условий оплаты сотрудников
Для расчёта зарплаты необходимо заполнить регистр сведений «Условия оплаты сотрудников» (периодичность — месяц).

Сотрудник	- Ссылка на сотрудника
Период -	Месяц, с которого действуют условия
Оклад -	Сумма месячного оклада
Процент от работ -	Процент от выполненных работ (для специалистов; для админ. персонала — 0)
Порядок заполнения:

Откройте регистр сведений «Условия оплаты сотрудников» (через «Расчет управленческой зарплаты» → «Регистры»).
Создайте записи по каждому сотруднику:
Для специалистов укажите оклад и процент от работ (например, оклад 10 000, процент 10%).
Для административного персонала укажите только оклад (процент — 0).
При изменении условий создавайте новые записи с новой датой начала периода.
Если на дату документа «Обслуживание клиента» специалисту не установлен процент от работ (запись отсутствует), документ не проведётся. Нулевой процент — допустим, документ проведётся.

------

### 5. Назначение ролей и профилей групп доступа
Разработанные роли и профили необходимо назначить пользователям.

Профили групп доступа
Профиль - Специалист,	Роли (кратко) - Чтение и редактирование документов «Обслуживание клиента», чтение регистра выполненных работ, отчёт «Выработка специалистов», Кому назначать -	Специалисты, выполняющие работы у клиентов
Профиль - Менеджер,	Роли (кратко) -	Создание и редактирование документов «Обслуживание клиента», просмотр договоров, работа с календарём специалистов, Кому назначать -	Менеджеры, принимающие заявки
Профиль - Бухгалтер ИТ Фирмы,	Роли (кратко) -	Работа с документами «Реализация товаров и услуг», обработка «Массовое создание актов», отчёт «Анализ выставленных актов», Кому назначать -	Бухгалтер
Профиль - Кадровик-Расчетчик,	Роли (кратко) -	Документы начисления зарплаты, премий, выплат, графиков отпусков, отчёты по зарплате и отпускам, отчёт «Выработка специалистов», Кому назначать -	Кадровик-расчётчик
Порядок назначения:

Откройте «Администрирование» → «Пользователи» → «Профили групп доступа».
Убедитесь, что поставляемые профили (Специалист, Менеджер, БухгалтерИТФирмы, КадровикРасчетчик) загружены в базу.
Назначьте соответствующие профили пользователям через «Пользователи» → вкладка «Группы доступа» (или через профили напрямую).
Перезапустите сеанс пользователей и проверьте видимость разделов и документов.

### Описание задания

Компания «Ваш компьютерный мастер» использует конфигурацию «Управление IT-фирмой» от стороннего поставщика. Вам поставлена задача добавить в конфигурацию модуль для работы с заявками на обслуживание клиентов и модуль для расчёта управленческой заработной платы.

Исходная версия конфигурации размещена в [этом репозитории](/fonecmid-diplom). Для доработки конфигурации нужно использовать 1C:EDT. При доработке конфигурации максимально задействуйте функциональность библиотеки стандартных подсистем.

Для добавленных объектов, реквизитов, методов используйте префикс ВКМ_. Если меняется программный код существующих методов, изменения должны быть выделены комментариями.

Все добавленные объекты должны быть размещены в новой служебной подсистеме ВКМ_ДобавленныеОбъекты. В добавленных объектах не должно быть ошибок, выявляемых встроенным механизмом проверки 1C:EDT.

Для передачи результата изменённую конфигурацию загрузите в отдельный репозиторий на [github.com](https://github.com). Чтобы результаты работы можно было проверить, репозиторий должен быть публичным.

Вместе с результатами работы должны быть переданы инструкция по начальной настройке новой подсистемы и сценарий для автоматизированного тестирования модуля работы с заявками клиентов.

В блок Releases репозитория должен быть добавлен dt-файл демонстрационной базы с введёнными тестовыми данными, которые показывают работу всех механизмов системы.

### Дорожная карта (roadmap)

Работа над проектом рассчитана на один месяц. Для планирования своего времени рекомендуем опираться на дорожную карту. Придерживайтесь указанного разделения проекта на этапы и задачи исполнителя.

- 1-я неделя. Разработка подсистемы «Работа с заявками клиентов».
- 2-я неделя. Разработка подсистемы «Расчёт управленческой зарплаты».
- 3-я неделя. Разработка отчётов, автотеста и инструкции по начальной настройке.
- 4-я неделя. Оформление репозитория, демонстрационной базы, отправка проекта на проверку дипломному руководителю.
- 5-я неделя. Получение обратной связи от руководителя и доработка проекта с повторной проверкой при необходимости.

### Правила сдачи работы

Решение нужно передать в виде ссылки на публичный репозиторий на github.com, в котором размещены:

1. Исходный код доработанной конфигурации в формате 1C:EDT.
2. Сценарий автотеста и инструкция по запуску автотеста.
3. Инструкция по начальной настройке доработанной конфигурации.
4. В списке релизов файл с демонстрационной базой в формате *dt.

------

### Критерии оценки

Зачёт по дипломной работе можно получить, если работа соответствует критериям:

1. Репозиторий содержит исходный код конфигурации в формате 1C:EDT.
2. Функциональность конфигурации не имеет существенных ошибок и соответствует техническому заданию.
3. В добавленных объектах нет ошибок, выявляемых проверками 1C:EDT с набором плагинов и составом проверок по умолчанию.
4. Автотест запускается и соответствует техническому заданию.
5. Инструкция по начальному запуску описывает шаги, необходимые для начала использования доработанной конфигурации.
6. Демонстрационная база содержит достаточный набор данных, соответствующий требованиям.
